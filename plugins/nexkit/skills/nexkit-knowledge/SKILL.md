# NexKit knowledge

Run `nexkit knowledge` to find the current consumer's sources and accepted
decisions. Read only what the current request needs. Prefer code and maintained
documentation as the source for facts; link to them rather than copying them.

When updating knowledge within an approved delivery, state the decision or
lesson, its reason, and the relevant source. Separate confirmed facts, inferences
and possibly stale information. Keep the change in the reviewed candidate.
Do not mix projects, record credentials, append raw transcripts or create a
parallel specification. Product requirements remain authoritative in their issue.
